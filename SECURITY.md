# Security Policy

## Supported version

Security fixes are applied to the latest release line (4.0.x). Older versions, including the 2.0 store build, are not patched.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, or user data. Use GitHub's private vulnerability reporting on this repository (Security tab, Report a vulnerability). If that button is not shown, open an issue asking for a private contact, with no details in it. Include affected version, reproduction steps, impact, and a minimal proof of concept where safe.

You should receive an acknowledgement within seven days. Please allow reasonable time for validation and a coordinated fix before public disclosure.

Never include a real provider key in a report. Revoke any key that may have been exposed.
